All notable changes to Praxis are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres, loosely, to [Semantic Versioning](https://semver.org/) —

## [Unreleased]

### Added

- **Antigravity agents ship tier-only (no Claude model names).** agy honors no per-agent model selection — subagents inherit the session model, hooks cannot set a model, and the SDK's `LocalAgentConfig` exposes no model field (verified against the CLI subagents doc, the hooks schema, and the SDK README). The canonical `agents/*.md` carry Claude `model:`/`effort:` frontmatter as Claude Code's static default; shipping those verbatim in the agy package advertised models agy can never use. `scripts/build-antigravity-plugin.sh` now strips `model:`/`effort:` from the agy agents, keeping the harness-agnostic `capability_tier:` (the real routing signal, resolved by hand via `/model` per the advisory tier map). Canonical agents are untouched (Claude Code still needs them). `scripts/validate-antigravity-plugin.sh` drops the byte-identical freshness check for agents and instead asserts every agy agent declares `capability_tier` and carries no `model:`/`effort:` line.
- **Antigravity telemetry hooks — wired (routing + activity), scoped to what `agy` exposes.** The Antigravity package now ships a self-contained `hooks.json` at its root (source: `antigravity-plugin-assets/hooks.json`, copied verbatim by the build), verified against `agy`'s hooks schema AND a live `agy` run. It logs the shared canonical `model-routing.jsonl` (as `event:model_invocation`) and `sessions.jsonl` (as `event:session_stop`), plus an agy-specific `antigravity-activity.jsonl` (tool audit) — every row carrying the canonical envelope (`ts`, `harness`, `event`, `session`) so harnesses share stream files and stay attributable by `harness` under the workspace `.project/telemetry/`. The hook is inline (no sibling script to lose on install), never blocks the loop (always emits the correct stdout contract; falls back if `python3` is absent), and self-scopes via `workspacePaths`. **Honest scope:** `agy` exposes NO token counts, NO cache read/write, NO dollar cost, and NO subagent-spawn events — not in the hook payloads, not in `transcript_full.jsonl` — so unlike the Claude Code / Codex `tap.sh`, Antigravity telemetry is **routing + activity, not cost**, by platform limitation. Fixed the root cause of the earlier silent failure: a Claude-format `{"hooks": {SessionStart|UserPromptSubmit|Subagent*…}}` manifest that `agy` counts as `hooks: 1 processed` but drops every handler (unknown events poison the strict protojson decode). `scripts/validate-antigravity-plugin.sh` now asserts the manifest is `agy`'s real format (top-level named hooks; only the five supported events) and rejects the Claude-format leak. `install.sh` copies the manifest on the workspace-install path too. This supersedes the prior “Antigravity has no hook wiring yet” note in `docs/antigravity-setup.md`.
- **Antigravity adapter absorbs the cache-aware-routing + infra-security work.** `antigravity-support` merged both feature branches, so the Antigravity package now ships the `database-engineer` agent, the `iac_plan_review` gate, and the cache-aware `adaptive-model-routing` guidance — they land automatically because `agy` reads the same canonical `agents/` / `skills/` / `governance/`. The *deterministic* enforcement pieces (`PreToolUse(Task)` cache-aware guard, `routing-preflight.py`, `iac-plan-classify.py`, `validate-review-coverage.py`) are `scripts/`- and hook-based and are **not** shipped in the package (Antigravity has no hook wiring yet), so on Antigravity they operate as agent-followed *guidance* rather than hard enforcement — stated in `docs/antigravity-setup.md`. Package rebuilt to 18 agents / 19 gates; fixed the one thing a copy-based rebuild can't catch — the hand-authored `cmd-start.md` overlay's stale `17 agents` count and a hardcoded `17` in `validate-antigravity-plugin.sh`.
- **`has_infrastructure` captured at `/start` on every harness.** `delivery-planner` already *set and acted on* the flag (activating the `iac` skill + `iac_plan_review` gate), but the human-facing `/start` charter prompt never *asked* for it. It is now enumerated in the charter capture across Claude Code (`.claude/commands/start.md`, `commands/start.md`), Codex (`codex-plugin-assets/skills/praxis-start`), and Antigravity (`cmd-start.md` overlay) — infrastructure governance is set explicitly at bootstrap rather than inferred.
- **`docs/antigravity-setup.md` — feature-branch + local-checkout install** sections, matching the Claude Code and Codex setup docs (adapted to Antigravity's local-path-only `agy plugin install`, which has no remote `@ref`).
- **`iac_plan_review` gate (19th gate) + destructive-change model.** A conditional governance gate (activated by the new `has_infrastructure` charter flag) that reviews the infrastructure PLAN — the computed create/update/replace/destroy set — not the IaC source, which generic code review is shaped wrong to catch (a one-line diff can force-replace a stateful resource). Destructive changes are classified A-E: (A) data-bearing destroy/replace, (B) IAM/RLS/grant change, (C) network-exposure change, (D) guardrail removed (deletion_protection off, force_destroy, etc.), (E) cascade replacement; each blocking class needs explicit evidence to clear. `scripts/iac-plan-classify.py` auto-detects and parses Terraform (`terraform show -json`), Pulumi (`pulumi preview --json`), and CloudFormation (`describe-change-set`) plans and fails closed on any un-dispositioned blocking change (the deterministic layer), backstopped by a `verdict_file` human review. Wired into `implementation-slice.yaml` as a conditional `pr_touches_iac` branch that gates merge alongside code/security/visual review, so infra changes are caught at the SLICE, not only at production go-live. Honest scope: this is a review checkpoint, not a runtime interceptor — it does not stop `terraform apply`/`destroy`; that stays a CI/runtime concern.
- **`has_infrastructure` charter flag** — set by `delivery-planner`; activates the `iac` skill and the `iac_plan_review` gate.
- **Review-coverage guard** (`scripts/validate-review-coverage.py`, wired into CI) — an intent-maintained allowlist asserting that a reviewer actually loads the security/quality checklists it is accountable for (not auto-derived from the fuzzy `consumers:` field, which would false-positive on ~138 benign asymmetries).
- **`database-engineer` agent (18th role).** A conditionally-activated Tier-2 specialist that owns the transactional (OLTP) database as an engineered system — DB-layer security (RLS policies, roles/grants), zero-downtime expand-contract migrations on live tables, index/partition/query-plan performance, and data-tier reliability (replication/pooling/backup-restore). Scoped to *complement* backend-developer, not duplicate it: routine schema/CRUD/migrations stay with backend-developer; physical data design stays with solution-architect (`data-modeling`); analytics/warehouse stay with data-engineer; provisioning stays with platform-sre. `capability_tier: standard` with explicit escalation to deep for RLS/grants and destructive migrations. Shipped for every harness: `agents/database-engineer.md` (source of truth, copied by the cursor/opencode/copilot/kiro/gemini/antigravity installers) + a Codex subagent profile `codex-plugin-assets/codex-agents/database-engineer.toml`; added to the `.claude-plugin/plugin.json` `agents` array, the `adaptive-model-routing` per-agent tier tables (Claude + Codex), PLAYBOOK, and getting-started. All "17 agents" counts bumped to 18 across install.sh, manifests, docs, and command definitions.
- **Cache-aware routing pre-flight guardrail** (`scripts/routing-preflight.py`). Deterministically enforces the cache-aware routing policy from recent telemetry: a context-heavy model-DOWN that would forfeit a warm prompt cache is auto-substituted with an effort-down (keep the model, lower the reasoning tier); up-routes and effort-only moves apply unchanged. Wired into `scripts/praxis-drive.sh` per iteration AND an interactive `PreToolUse(Task)` hook that denies a cache-forfeiting down-spawn with a corrective re-spawn instruction. Every decision appends an `event:"routing_preflight"` audit record to `.project/telemetry/model-routing.jsonl`. Config under `preflight:` in `governance/model-routing.yaml`.
- `/intake` (`$praxis-intake`) — a single steady-state front door for new requirements, so you never pick a workflow by hand. The `requirements-intake` discipline (triage size + blast radius + owner, sequence, route) already existed as a skill but had no command, which forced manual routing per story/epic. `/intake` fronts it: drop any new story/ticket/change and it logs to `.project/working/inbox.md`, right-sizes, and routes to the lightest safe path (small ready story → slice + `/drive`; touches existing behavior → impact-analysis first; epic/cross-cutting → discover + architect + project-phasing; unproven → spike; P0/P1 → expedited-change), preventing FIFO churn and impulse coding. Wired for all harnesses (Claude/Gemini command files + Codex command skill), registry counts auto-updated (11→12 commands), and the `using-praxis` router + `docs/drive-first-playbook.md` steady-state section now point at it.
- Drive and no-drive now route identically (single source of truth). Previously a spawn's model came from the drive runner (which read the effective table) in drive, but from the baked agent profile (plugin default) in no-drive — so a project override only affected drive. Now one rule governs every spawn: `resolve(tier, harness)` against the effective table (`.project/governance/model-routing.yaml` first, plugin default fallback), with `force_tier` applied. New `scripts/resolve-model.py` is the shared resolver; `adaptive-model-routing` / `delivery-lead` / `using-praxis` now resolve through it and pass the model at spawn (Claude Code's per-invocation `model:` beats frontmatter); `scripts/setup-claude-agents.sh` (+ `apply-model-routing.py --claude-out`) materializes project-local `.claude/agents/*.md` that shadow the plugin so the static fallback is override-correct too. `scripts/test-routing-parity.sh` asserts the resolver and the drive runner agree for every tier on both harnesses and that an override moves both together. Fixed a latent bug the parity test caught: the drive runner ignored `overrides.force_tier` — it now honors it, matching the resolver and the governance intent ("force every agent to that tier").
- Project routing overrides now reach the Codex subagent profiles. Previously the `.codex/agents/*.toml` were generated from the PLUGIN's `model-routing.yaml` at build time, so a project-level `.project/governance/model-routing.yaml` override (which the drive loop already honors at runtime) never affected the static subagent profiles — you'd have had to hardcode models in the plugin defaults. Now `apply-model-routing.py` takes `--routing` / `--project-dir` (read the project override, falling back to the plugin default) and `--codex-out DIR` (write the resolved `model` / `model_reasoning_effort` into a target `.codex/agents/`, leaving the plugin's own files untouched), and `$praxis-setup-subagents` runs it on install/refresh. Set `model_map` (pin models) or `map` (effort) in your project override and re-run setup-subagents to propagate — no plugin edits. Default `model_map: auto` still writes no `model` line (subagents inherit the Codex session model). Re-running also refreshes stale effort values (the reason a `standard`-tier agent could still show `high` after a tier rebalance).
- Governance-override drift detection + non-destructive refresh. `.project/governance/{model-routing,autonomy}.yaml` are seeded once and win over the plugin's copies (so per-engagement tuning survives updates) — which meant new default keys from a plugin update (e.g. the codex `effort_flag`/`effort_arg_prefix` that enable per-iteration reasoning-effort routing) never reached an existing project. Docs: `docs/codex-setup.md` refresh checklist + `INSTALLATION.md` §6.

### Fixed

- **Antigravity command-skills now ship nested (`skills/<name>/SKILL.md`), so `agy` discovers them.** The 12 workflow command-skills were authored as flat `antigravity-plugin-assets/skills/cmd-*.md` on the assumption (flagged as unverified in `docs/antigravity-setup.md`) that `agy` would register flat `skills/*.md` carrying a `name:` key.
